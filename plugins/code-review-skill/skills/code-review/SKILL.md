# 代码评审清单

对给定代码变更做系统性评审，产出可执行的分级问题清单。评审对象优先级：
用户给的 diff > 指定文件 > 用户粘贴的代码片段。

## 评审维度（按序过一遍）

1. **正确性** — 逻辑错误、边界条件（空值/零值/越界/并发）、错误处理路径；
2. **安全** — 注入、敏感信息硬编码、越权、不安全反序列化、SSRF；
3. **数据与事务** — 一致性、幂等、并发写、N+1 查询、缺索引的高频路径；
4. **接口契约** — 参数校验、返回结构稳定性、向后兼容、超时与重试语义；
5. **可读性** — 命名、函数长度、重复代码、误导性注释；
6. **测试** — 关键路径有无覆盖、断言是否有效、边界用例；
7. **性能** — 明显的算法级问题（嵌套循环、重复 IO），不抠微优化。

## 问题分级

| 级别 | 含义 | 处置 |
|------|------|------|
| **P0** | 正确性/安全缺陷，必须改 | 阻塞合入 |
| **P1** | 明显风险或契约问题 | 建议本次改 |
| **P2** | 可读性/测试/性能改进 | 可后续跟进 |

## 输出格式

1. **结论先行**：一段话总评（可合入 / 改后合入 / 需重新设计）；
2. **问题清单**：`级别 | 位置 | 问题 | 建议`，位置精确到文件与行号/函数名；
3. **亮点**（可选）：值得保持的做法，最多 3 条；
4. 无问题的维度不展开写，一句"其余维度未见问题"即可。

## 评审纪律

- 只评审给定变更范围，不顺手重构无关代码；
- 每条问题必须给出**具体修改建议**，不写"建议优化"这类空话；
- 不确定的问题标注"待确认"并说明验证方法；
- 风格偏好类问题（命名口味、格式）最多列 1 条，且只能是 P2。
