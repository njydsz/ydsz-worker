# 设计批评框架 (Design Critique Framework)

## 概述

本框架融合了 UX Crítica（拉丁美洲 UX 传统）和日本デザイン批评的设计评审方法论，提供一套可复用的结构化评审流程。核心原则：**批评针对设计，不针对设计师**——聚焦问题、提供建设性改进建议。

适用于 Figma/Sketch/Adobe XD 等主流设计工具，覆盖 B 端仪表盘、C 端 App、响应式 Web 等场景。

## 6 维度评审框架

评审时逐维度扫描，每个维度用 0-4 分打分（0=未涉及，1=严重问题，2=需改进，3=合格，4=优秀）。

### 维度 1：可用性 (Usability)

- **核心问题**：用户能否快速、准确地完成任务？
- **关键检查点**：
  - 主要任务流是否在 3 步内可达？
  - 关键操作按钮在 Fitts' Law 热区内是否有足够尺寸？
  - 导航层级是否过深（>3 层需警示）？
  - 空状态、加载态、错误态是否都有设计？
  - 搜索/筛选结果排序逻辑是否符合用户心智模型？

### 维度 2：一致性 (Consistency)

- **核心问题**：设计语言在整个产品/跨页面中是否统一？
- **关键检查点**：
  - 字号梯度和间距系统是否遵循 baseline grid（如 4px 基准）？
  - 同类组件（按钮/卡片/输入框）交互状态是否一致？
  - 文案语调、术语、数字/日期格式是否统一？
  - 跨端体验（iOS/Android/Web/H5）核心流程是否对齐？
  - Icon 风格是否统一（面性/线性/圆角/尺寸）？

### 维度 3：可访问性 (Accessibility)

- **核心问题**：所有用户（包括残障用户）能否正常使用？
- **关键检查点**：
  - 色彩对比度是否达标（WCAG AA: 正文 ≥4.5:1，大文本≥3:1；AAA 更严）？
  - 触摸目标尺寸 ≥ 44×44 pt（iOS）或 48×48 dp（Android）？
  - 是否仅依赖颜色传达信息（红绿色盲不可区分）？
  - 键盘/屏幕阅读器能否完整导航（Tab 顺序、焦点环、ARIA 标签）？
  - 动画是否提供 `:prefers-reduced-motion` 降级方案？

### 维度 4：视觉层级 (Visual Hierarchy)

- **核心问题**：用户第一眼看哪里？注意力引导是否有效？
- **关键检查点**：
  - 页面是否有明确的视觉焦点（F 型或 Z 型扫读路径）？
  - 主操作（CTA）是否在视觉权重上「最重」？
  - 对比度/留白/字体粗细是否创造了清晰的层级？
  - 信息密度是否过高（一屏内元素超过 7±2 组块需警惕）？
  - 折叠线上方是否承载了核心价值主张？

### 维度 5：品牌一致性 (Brand Alignment)

- **核心问题**：设计是否传达了品牌调性？
- **关键检查点**：
  - 是否使用了品牌色板（主色/辅助色/语义色）？
  - 字体是否为品牌规范字体（中英文分别检查）？
  - 插画/摄影/图标风格是否符合品牌视觉手册？
  - 微文案语气是否与品牌人设匹配（专业/活泼/高端）？

### 维度 6：情感化设计 (Emotional Design)

- **核心问题**：设计是否创造了积极的感官体验？
- **关键检查点**：
  - 微交互是否有适当的动效反馈（时长 200-500ms 区间）？
  - 庆祝/成功时刻是否有情感化惊喜（Lottie/Confetti）？
  - 错误/忧郁场景是否有共情设计（而非冷冰冰的技术报错）？
  - 文案是否有人味（「操作失败，请重试」vs「抱歉，出了点小状况」）？

## 启发式评估流程 (Heuristic Evaluation)

推荐 3-5 名评审员各自独立走查后聚合。

### 阶段 1：独立走查（每屏 15-30 分钟）

1. **预读材料**：阅读 PRD、用户画像、竞品分析。
2. **任务流走查**：按用户核心路径逐步骤操作原型。
3. **维度扫描**：按 6 维度逐项检查，记录截图+批注。
4. **严重度打分**：按 4 级严重度评估每个发现。
5. **建议草稿**：每个问题附带 1-2 个改进方向。

### 阶段 2：会审聚合（60-90 分钟）

1. **汇总去重**：合并多人发现的相同问题，取最高严重度。
2. **投票聚焦**：按「严重度 × 影响范围」排序，聚焦 P0/P1 问题。
3. **方案共创**：针对 Top 问题进行头脑风暴，产出具体修改建议。
4. **报告定稿**：生成评审报告。

### 阶段 3：Follow-up 验证

- 修改完成后由原评审员确认修复。
- 建立「历史问题库」防止同类问题复发。

## 严重度分级 (Severity Rating)

| 等级 | 名称 | 定义 | 处理要求 |
|------|------|------|----------|
| S0 | Critical | 阻断核心功能/法律风险/安全漏洞 | 必须修复，不可上线 |
| S1 | Major | 显著影响使用效率/造成严重困惑 | 当前迭代修复 |
| S2 | Minor | 体验瑕疵，用户可绕过或适应 | 排入待办，按优先级处理 |
| S3 | Cosmetic | 纯粹视觉偏好，无功能影响 | 低优先级或不做修改 |

## Design Token 一致性检查清单

适用于使用 Design Token 体系的项目：

| 检查项 | 确认方式 |
|--------|----------|
| 颜色 Token 命名是否语义化（`color-bg-primary` 而非 `color-blue-500`） | 对照 Token 表 |
| 间距是否步进制（4/8/12/16/24/32/48） | Figma Inspect |
| 字号与行高比例是否为 Token 定义值 | DevTools 核对 |
| 圆角是否沿用 Token（small/medium/large） | Figma Inspect |
| 阴影层级（elevation-0/1/2/3）是否对应 Token | 对照规范 |
| 深色模式是否有独立 Token 对照表 | 切换 Theme 测试 |

## Figma 评审实用技巧

- **Inspect 面板**：选中元素查看间距/颜色/字体/圆角/代码 Snippet。
- **Version History**：<version> → Save Version 创建评审快照，命名如 `v1.2-review`。
- **Comment 工具**：Ctrl/Cmd + / 在画布上直接批注，@提及设计师。
- **Link 引用**：复制 Frame 链接粘贴到评审报告，确保所指精确。
- **多人协作指针**：评审时观察多人光标，可实时讨论区域。
- **Prototyping 评审**：切换至 Prototype 模式走查交互流，检查 Transition 参数。
- **UI Kit 切齐检查**：Align 插件检测元素是否贴齐 grid/组件。
- **Accessibility 插件**：Stark / A11y — 直接检测对比度、色盲模拟、焦点顺序。

## 适用场景速查

| 场景 | 评审侧重 |
|------|----------|
| B 端仪表盘 | 信息密度、数据可视化、键盘快捷键 |
| C 端 App | 手势交互、情感化、品牌调性 |
| RWD 响应式 | Breakpoint 规划、断点间一致性 |
| ToB SaaS | 效率优先、批量操作、权限差异 |
| 国际化/RTL | 文本扩展、RTL 镜像、日期/数字格式 |
